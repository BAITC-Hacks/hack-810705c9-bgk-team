# AI-Sana — рабочее пространство

Рабочее пространство для бизнеса: задачи слева, расширенный чат в центре, отклики справа. Карточка задачи открывается в отдельной боковой панели, сохраняя переписку и набранное сообщение. Несохранённые правки карточки сохраняются локально при закрытии и повторном открытии; публикация по-прежнему требует подтверждения. На узком экране задачи и отклики открываются поверх чата. Студенты видят общий каталог на всю ширину, без чата: поиск, фильтры по теме и готовности, выбор команды и свои отклики. Нажатие на строку задачи открывает сведения и форму предложения в боковой панели; закрытие сохраняет фильтры каталога.

Во всём интерфейсе используется Roboto с кириллицей через `next/font/google`, белые поверхности и нейтральный тёмный текст. Иконки рабочего пространства — `@gravity-ui/icons`; декоративные иконки сведены к минимуму. Фильтры и выбор числа участников используют стилизованный Radix Select с поддержкой клавиатуры.

В режиме бизнеса компактная панель иконок управляет списком задач, карточкой, откликами и разворотом чата. Действия подписаны во всплывающих подсказках. Возврат из развёрнутого чата восстанавливает предыдущую ширину колонок; набранный текст сохраняется. Заголовки используют жирное начертание, основной текст чата — 15 px, навигация и действия — полужирное. Прокрутка остаётся нативной, с тонкими закруглёнными полосами.

Действия «Выбрать команду» / «Отклонить» и переходы между откликами закреплены внизу панели бизнеса. Длинные описания и планы прокручиваются отдельно, а подтверждение этапа остаётся в сведениях выбранной команды.

## Клавиатура и навыки чата

Кнопка темы в верхней панели переключает светлый, тёмный и системный режимы. Предпочтение сохраняется в браузере; системный режим следует настройкам устройства. Тема применяется к обоим рабочим пространствам, боковым панелям, меню, полям и уведомлениям.

Микрофон в чате бизнеса запускает голосовой ввод на русском. Распознанный текст дополняет набранный черновик; его можно проверить и отредактировать перед отправкой. Голосовой ввод не отправляет сообщение автоматически. При смене задачи, роли или скрытии вкладки микрофон выключается. Ошибки доступа и неподдерживаемый браузер объясняются рядом с полем.

Используется браузерный [Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition), без нового API приложения или ключей. Поддержка зависит от браузера; распознавание может обращаться к сервису браузера и требовать интернет. Запись начинается только по нажатию микрофона. Работа с реальным микрофоном требует отдельной проверки на устройстве пользователя.

| Клавиши | Бизнес | Студент |
| --- | --- | --- |
| Ctrl / ⌘ + K | Фокус на сообщении | Фокус на поиске |
| Alt + 1 | Показать / скрыть список задач | — |
| Alt + 2 | Открыть / закрыть редактор карточки | Открыть / закрыть выбранную задачу |
| Alt + 3 | Показать / скрыть отклики | Открыть / закрыть выбор команды |
| Alt + 0 | Развернуть / свернуть чат на широком экране | — |
| Esc | Закрыть верхнее меню или боковую панель | Закрыть верхнее меню или диалог |
| ? вне поля ввода | Подсказка по клавишам | Подсказка по клавишам |

В сообщении введите `@` или нажмите одноимённую иконку. Доступны «Уточнить задачу», «Проверить готовность», «Критерии успеха», «Сравнить отклики», а также переходы в карточку и отклики. Меню фильтруется по русским названиям и английским псевдонимам (`@score`, `@brief`, `@compare`). Стрелки выбирают строку, Enter или Tab выбирают действие, Esc закрывает меню. Выбранный навык отображается в сообщении и выполняется только после отправки; его можно удалить. Shift + Enter добавляет новую строку. `@` в адресе электронной почты не открывает меню.

Навыки — детерминированные локальные функции, использующие сведения текущей задачи и существующие отклики. Они не вызывают модель, не дописывают факты, не публикуют карточку и не выбирают команду. Нажатия клавиш не проходят сквозь открытые диалоги и выпадающие списки; после закрытия панели фокус возвращается в рабочую область.

В чате «Демо-ассистент» открывает промпт, JSON входа и выхода локальной заглушки. «Показать обработку ошибки» демонстрирует неверный JSON и безопасный запасной ответ (`parse_ok: false`, `fallback_used: true`). Контракт в `src/_pages/workspace/ui/local-ai-analysis.ts` проверяет структуру и соответствие исходной карточке; ответ не меняет её поля. Вопросы задаются только о пустых полях: заполненные ответы ожидают проверки в редакторе.

Кнопка «Моя команда» открывает профили команд: можно сравнить навыки и интересы, выбрать другую команду, изменить текущий профиль или создать новый. Отклики и баллы связаны с ID команды и сохраняются при переключении и переименовании. Это локальное переключение демо-профилей; оно не добавляет авторизацию или реальные приглашения участников.

Интерфейс подключён к Next.js API и PostgreSQL `nextjs_db` через Drizzle. Задачи, подтверждённые поля, команды, отклики, результаты этапов и история оценок хранятся в БД. Переключатель «Бизнес / Студент» и выбранная команда сохраняются в HTTP-only cookie. Это общий демонстрационный workspace без регистрации: переключение роли разрешено каждому участнику, оно не заменяет авторизацию. Настоящий AI и коннекторы в этот backend не входят; ассистент сохраняет существующие локальные сценарии.

Сохранённые изменения переживают обновление страницы. В памяти вкладки остаются переписка и несохранённый ввод. Действие обновления в меню «Демо» перечитывает БД, сохраняя локальную беседу и ввод; сохранённые записи не удаляются. Seed содержит 6 опубликованных задач, 6 черновиков, 6 команд, 7 откликов и один подтверждённый этап. Все компании и сведения вымышлены; ссылки на `example.com` служат примерами. Повторный `db:seed` добавляет только отсутствующие записи и не перезаписывает правки.

## Запуск

Нужны Bun 1.4.2 и Node.js >=24. Из корня репозитория:

```sh
bun install --frozen-lockfile
./start.sh
```

`start.sh` запускает инфраструктуру, применяет миграции и заполняет демо (отключение seed: `SEED_DEMO_DATA=0`). Для запуска только UI/BFF при уже работающей локальной PostgreSQL создайте `nextjs_db`, настройте `DATABASE_URL_NEXTJS` в `apps/presentation-layer/.env` по примеру и выполните:

```sh
cd apps/presentation-layer
bun run db:migrate
bun run db:seed
bun run dev
```

Откройте [localhost:3000](http://localhost:3000). Для основных действий нужна PostgreSQL; Mastra и ключи моделей не нужны. Docker Compose может запустить только базу: `docker compose -f docker-compose.dev.yml up -d postgres` из корня. Генерацию новых миграций выполняет владелец схемы командой `db:generate`; остальные применяют готовые SQL через `db:migrate`.

## Показ за пять минут

1. В режиме бизнеса создайте черновик и опишите проблему своими словами. Ассистент покажет три уточняющих вопроса.
2. Нажмите на вопрос и отправьте ответ. Текст без изменений попадёт в выбранное поле карточки; неподтверждённый ответ пока не повышает оценку. Повторите для остальных вопросов.
3. Откройте «Карточка задачи», проверьте формулировки и отметьте подтверждение заполненных полей. Посмотрите предварительную оценку и нажмите «Подтвердить и опубликовать».
4. Переключитесь в режим студента. Найдите опубликованную задачу, выберите команду и нажмите «Предложить решение». Заполните идею, план, срок и ссылку на прототип, например `https://example.com/demo/my-prototype`, затем отправьте отклик.
5. Вернитесь в режим бизнеса. Отклик появится справа: рассмотрите его, выберите команду или отклоните предложение. Можно отменить решение, выбрать несколько команд или не выбирать никого — автоматического назначения нет.
6. В режиме студента откройте свой выбранный отклик и нажмите «Сдать этап». Укажите название выполненного этапа, ссылку на результат и что сделано. До подтверждения можно изменить результат; отправка сама по себе не приносит баллов.
7. В режиме бизнеса проверьте результат и вручную подтвердите этап. Команда получает 10 демонстрационных баллов один раз за этот отклик. Повторное подтверждение, отмена выбора и повторный выбор не начисляют баллы снова. В режиме студента проверьте статус и баллы.

Опубликованные задачи доступны для отклика при любой готовности. Низкая оценка помогает увидеть пробелы, но не блокирует публикацию или участие. Публикация и изменение публичной карточки требуют подтверждения текста бизнесом.

## Готовность задачи

Баллы начисляются только за непустые подтверждённые поля. При изменении поля его нужно подтвердить заново. Неизменённые подтверждённые поля сохраняют баллы.

| Категория              |                                Максимум |
| ---------------------- | --------------------------------------: |
| Контекст и потребность |               20 — по 10 за каждое поле |
| Данные и материалы     |                                      20 |
| Ожидаемый результат    |                                      15 |
| Критерии успеха        |                                      15 |
| Ограничения            |                                      10 |
| Пользователи           |                                      10 |
| Связь с бизнесом       | 10 — контакт 5, формат взаимодействия 5 |
| **Итого**              |                                 **100** |

Уровни: 0–39 — требует уточнения; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. Статус публикации независим от уровня: даже задачу с 10 баллами можно подтвердить, опубликовать и получить отклики. Каталог сортируется по убыванию подтверждённой готовности; изменения публичной карточки появляются только после сохранения и ручного подтверждения.

Первая опубликованная задача «Снизить списания в пекарне» имеет 70 баллов и три отклика. В каталоге есть опубликованный пример с 25 баллами для проверки доступности задач с неполным брифом.

## Где находится код

| Модуль                         | Ответственность                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------- |
| `src/entities/workspace`       | Типы, расчёт готовности, вопросы, демонстрационные данные и тесты модели        |
| `src/features/task-editor`     | Редактирование, подтверждение полей и публикация карточки                       |
| `src/features/task-inspector`  | Просмотр откликов, форма предложения, выбор команды и подтверждение этапа       |
| `src/features/student-catalog` | Общий каталог, поиск, фильтры, выбор команды и панель сведений                  |
| `src/features/team-picker`     | Просмотр, выбор, создание и редактирование профиля команды                      |

Публичные импорты проходят через `index.ts` соответствующего модуля. Все UI callbacks сейчас изменяют локальное состояние страницы.

## API и данные

Все перечисленные маршруты реализованы; JSON-входы проверяются Zod. Ошибки: `{ "error": { "code": "...", "message": "..." } }`, при ошибке валидации дополнительно `fields`. Роли проверяются на сервере. Студент получает только опубликованные карточки с подтверждёнными полями и отклики выбранной команды. UI показывает загрузку, ошибку и повтор запроса, а формы сохраняют ввод при неудачной отправке.

| Метод и маршрут                      | Назначение                                                 |
| ------------------------------------ | ---------------------------------------------------------- |
| `GET /api/workspace`                 | Согласованный снимок `{tasks, teams, proposals, session}` |
| `GET /api/session`, `PATCH /api/session` | Текущие роль и команда, переключение демо-профиля |
| `GET /api/tasks`, `GET /api/tasks/:id` | Задачи с проверкой видимости |
| `POST /api/tasks`                    | Создать черновик из описания                               |
| `PATCH /api/tasks/:id`               | Сохранить полную карточку с текущей `version`; `status: published` публикует после проверки подтверждений |
| `GET /api/tasks/:id/score`           | Строгий JSON: `score`, `level`, `verdict`, семь `breakdown`, `missing`, `recalculation` |
| `GET /api/tasks/:id/score/history`   | Последние 100 сохранённых оценок для бизнеса |
| `GET /api/catalog?q=&industry=&level=` | Публичный каталог с фильтрами и сортировкой |
| `GET /api/teams`, `POST /api/teams`, `PATCH /api/teams/:id` | Профили команд |
| `GET /api/tasks/:id/proposals`, `POST /api/tasks/:id/proposals` | Список откликов / новый отклик выбранной команды |
| `POST /api/proposals/:id/decision`   | `{status: pending|selected|rejected}`; решение бизнеса |
| `PUT /api/proposals/:id/milestone`   | `{title, resultUrl, comment}` — результат выбранной команды |
| `POST /api/proposals/:id/milestone/confirm` | Подтверждение результата, безопасное при повторе |
| `GET /api/proposals/:id/kickoff`     | Подтверждённые материалы, контакт и первый этап после выбора |
| `GET /api/teams/:id/progress`        | Подтверждённые результаты и баллы команды |

Схема: `businesses → tasks → task_fields / score_events / proposals`, `teams → proposals → milestones`. Внешние ключи, уникальность `(task_id, team_id)`, состояния и диапазоны защищены PostgreSQL. Изменения карточки и история оценки фиксируются одной транзакцией; устаревшая `version` возвращает 409. Решения и этапы блокируют строку отклика, поэтому повторные и параллельные подтверждения не удваивают баллы. Подтверждённый результат нельзя изменить, его баллы сохраняются после отмены выбора. Бизнес может выбрать несколько команд.

Код: `src/shared/db` — схема/миграции/seed; `src/entities/workspace/contracts.ts` — входы и формат оценки; `src/server/workspace` — сервис и HTTP-обработка; `app/api` — маршруты. Контракт соответствует реализованному UI: один итоговый этап на отклик, девять полей и семь групп готовности. Полный 17-узловой анализ, рекомендации/свайпы и многоэтапные критерии из расширенной спецификации не добавлены этим изменением. Workspace snapshot рассчитан на объём демо; для большого каталога требуется серверная пагинация. AI остаётся в `ai-logic-layer`/Mastra; обращений к `mastra_db` нет.

## Проверка

Команды из `apps/presentation-layer`:

```sh
bun run check-types
bun run build
bun run lint -- src/_pages/workspace src/features/student-catalog src/features/team-picker src/features/task-editor src/features/task-inspector src/entities/workspace
bun test src
bun run test:backend
```

`test:backend` требует запущенный сервер и БД, использует `TEST_BASE_URL` (по умолчанию localhost:3000), создаёт временные задачи/команды и удаляет только собственные записи через `DATABASE_URL_NEXTJS`. Проверяет роли, сохранение после повторного чтения, историю оценки, конфликт редактирования, уникальность отклика, несколько выбранных команд и начисление ровно 10 баллов при параллельном подтверждении.

Короткая проверка UI:

- В режиме бизнеса на широком экране видны три панели; на узком доступны задачи, чат и отклики через переключатели.
- В режиме студента виден каталог всех опубликованных задач по убыванию готовности, включая 25-балльную карточку. Чата нет; поиск, фильтры и «Мои отклики» работают вместе. Сведения и отклик открываются в боковой панели.
- Новый черновик показывает три вопроса; ответ сохраняется именно в выбранное поле.
- Без подтверждения поля не добавляют баллы, публичные изменения не сохраняются без проверки текста.
- Опубликованная задача с низкой оценкой доступна студенту; отправленный отклик виден бизнесу.
- Выбор, отклонение и отмена решения отражаются у студента; подтверждённый этап даёт ровно 10 баллов.
- Обновление демо перечитывает БД без удаления сохранённых задач, команд и результатов. Переписка и незавершённый ввод остаются локальными; основные действия обращаются только к собственному API.
- В «Моя команда» смена профиля обновляет «Мои отклики» и баллы. Создание выбирает новую команду; редактирование имени сохраняет её отклики. Форма требует название и 3–5 участников.
