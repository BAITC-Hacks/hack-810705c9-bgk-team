# AI-Sana — рабочее пространство

Рабочее пространство для бизнеса: задачи слева, расширенный чат в центре, отклики справа. Карточка задачи открывается в отдельной боковой панели, сохраняя переписку и набранное сообщение. Несохранённые правки карточки сохраняются локально при закрытии и повторном открытии; публикация по-прежнему требует подтверждения. На узком экране задачи и отклики открываются поверх чата. Студенты видят общий каталог на всю ширину, без чата: поиск, фильтры по теме и готовности, выбор команды и свои отклики. Нажатие на строку задачи открывает сведения и форму предложения в боковой панели; закрытие сохраняет фильтры каталога.

Во всём интерфейсе используется Roboto с кириллицей через `next/font/google`, белые или угольно-серые поверхности в зависимости от темы. Иконки рабочего пространства — `@gravity-ui/icons`; декоративные иконки сведены к минимуму. Фильтры и выбор числа участников используют стилизованный Radix Select с поддержкой клавиатуры.

В режиме бизнеса компактная панель иконок управляет списком задач, карточкой, откликами и разворотом чата. Действия подписаны во всплывающих подсказках. Возврат из развёрнутого чата восстанавливает предыдущую ширину колонок; набранный текст сохраняется. Заголовки используют жирное начертание, основной текст чата — 15 px, навигация и действия — полужирное. Прокрутка остаётся нативной, с тонкими закруглёнными полосами.

Действия «Выбрать команду» / «Отклонить» и переходы между откликами закреплены внизу панели бизнеса. Длинные описания и планы прокручиваются отдельно, а подтверждение этапа остаётся в сведениях выбранной команды.

## Клавиатура и навыки чата

Кнопка темы в верхней панели переключает светлый, тёмный и системный режимы. Предпочтение сохраняется в браузере; системный режим следует настройкам устройства. Тема применяется к обоим рабочим пространствам, боковым панелям, меню, полям и уведомлениям.

Микрофон в чате бизнеса запускает голосовой ввод на русском. Распознанный текст дополняет набранный черновик; его можно проверить и отредактировать перед отправкой. Голосовой ввод не отправляет сообщение автоматически. При смене задачи, роли или скрытии вкладки микрофон выключается. Ошибки доступа и неподдерживаемый браузер объясняются рядом с полем.

Используется браузерный [Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition), без нового API приложения или ключей. Поддержка зависит от браузера; распознавание может обращаться к сервису браузера и требовать интернет. Запись начинается только по нажатию микрофона. Работа с реальным микрофоном требует отдельной проверки на устройстве пользователя.

| Клавиши | Бизнес | Студент |
| --- | --- | --- |
| Ctrl / ⌘ + K | Фокус на сообщении | Фокус на поиске |
| Alt + 1 | Показать / скрыть список задач | — |
| Alt + 2 | Открыть / закрыть редактор карточки | Открыть / закрыть выбранную задачу |
| Alt + 3 | Показать / скрыть отклики | Открыть / закрыть выбор команды |
| Alt + 4 | Открыть / закрыть документы задачи | — |
| Alt + 0 | Развернуть / свернуть чат на широком экране | — |
| Esc | Закрыть верхнее меню или боковую панель | Закрыть верхнее меню или диалог |
| ? вне поля ввода | Подсказка по клавишам | Подсказка по клавишам |

В сообщении введите `@` или нажмите одноимённую иконку. Доступны «Уточнить задачу», «Проверить готовность», «Критерии успеха», «Сравнить отклики», а также переходы в карточку, документы и отклики. Меню фильтруется по русским названиям и английским псевдонимам (`@score`, `@brief`, `@compare`, `@docs`). Стрелки выбирают строку, Enter или Tab выбирают действие, Esc закрывает меню. Выбранный навык отображается в сообщении и выполняется только после отправки; его можно удалить. Shift + Enter добавляет новую строку. `@` в адресе электронной почты не открывает меню.

Навыки — детерминированные локальные функции, использующие сведения текущей задачи и существующие отклики. Они не вызывают модель, не дописывают факты, не публикуют карточку и не выбирают команду. Нажатия клавиш не проходят сквозь открытые диалоги и выпадающие списки; после закрытия панели фокус возвращается в рабочую область.

В чате «О помощнике» объясняет возможности ассистента; раздел «Технические сведения» открывает промпт, JSON входа и выхода локальной заглушки. «Показать обработку ошибки» демонстрирует неверный JSON и безопасный запасной ответ (`parse_ok: false`, `fallback_used: true`). Контракт в `src/_pages/workspace/ui/local-ai-analysis.ts` проверяет структуру и соответствие исходной карточке; ответ не меняет её поля. Вопросы задаются только о пустых полях: заполненные ответы ожидают проверки в редакторе.

Кнопка «Моя команда» открывает профили команд: можно сравнить навыки и интересы, выбрать другую команду, изменить текущий профиль. Отклики и баллы связаны с ID команды и сохраняются при переключении и переименовании. Это локальное переключение демо-профилей; оно не добавляет авторизацию или реальные приглашения участников.

Интерфейс подключён к Next.js API и PostgreSQL `nextjs_db` через Drizzle. Задачи, подтверждённые поля, команды, отклики, результаты этапов и история оценок хранятся в БД. Переключатель «Бизнес / Студент» и выбранная команда сохраняются в HTTP-only cookie. Это общий демонстрационный workspace без регистрации: переключение роли разрешено каждому участнику, оно не заменяет авторизацию. Свободный чат использует настроенный Mastra agent; вопросы по полям и навыки сохраняют локальные сценарии.

Сохранённые изменения переживают обновление страницы. В памяти вкладки остаются переписка и несохранённый ввод. Действие обновления в меню «Помощь» перечитывает БД, сохраняя локальную беседу и ввод; сохранённые записи не удаляются. Seed содержит 6 опубликованных задач, 6 черновиков, 6 команд, 7 откликов и один подтверждённый этап. Все компании и сведения вымышлены; ссылки на `example.com` служат примерами. Повторный `db:seed` добавляет только отсутствующие записи и не перезаписывает правки.

## Демо-роли и доступ (ADR-008)

**Демо-режим, без аутентификации.** Выбор бизнеса или команды сохраняется в cookie. `/onboarding` позволяет заполнить профиль бизнеса с логотипом либо выбрать существующую команду. Рабочее пространство и подробный сценарий `/task-match` используют общего актора.

| Cookie | Значения | Флаги |
| --- | --- | --- |
| `tm_role` | `business` \| `team` | `httpOnly`, `sameSite=lax`, `path=/` |
| `tm_actor` | id бизнеса или команды из `src/shared/config/demo-actors.ts` | `httpOnly`, `sameSite=lax`, `path=/` |
| `tm_view` | `deck` \| `grid` | `sameSite=lax`, `path=/`, без `httpOnly` (как `setViewMode` в ADR-006) |

Cookie можно подделать, поэтому проверки роли и владения в use-case (`403`) защищают сценарий от ошибок UI, а не от злоумышленника. **Не разворачивайте приложение за пределами локального демо без замены механизма.**

Где код: `src/shared/lib/demo-actor.ts` и `demo-actor.server.ts` — разбор cookie и проверки владения; `src/entities/access` — видимость карточек и откликов; `src/server/workspace` — адаптер актуального UI к каноническим сервисам и onboarding. In-memory use-case заглушки удалены.

API проверяет роль и владение ресурсом; неверный актор получает `403`. Переключение в рабочем пространстве записывает сессию на сервере. Подробный сценарий `/task-match` использует те же проверки.

## Документы бизнеса

Скрепка в чате, `@docs` или `Alt + 4` открывают материалы текущей задачи. Можно выбрать несколько файлов или перетащить их в область добавления: PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX, TXT, MD, CSV, RTF. Ограничение — 10 файлов на задачу, до 10 МБ каждый. Повторные файлы не добавляются; ошибки отдельных файлов не мешают принятым документам.

Документы хранятся только в памяти текущей вкладки, отдельно для каждой задачи. Переключение задач и ролей их сохраняет, обновление страницы или закрытие вкладки удаляет. Файлы не отправляются на сервер, не показываются студентам и не передаются ассистенту; прикрепление само по себе не меняет рейтинг. PDF просматриваются в изолированном фрейме, TXT/MD/CSV — как обычный текст с ограничением размера предпросмотра; остальные форматы можно скачать и открыть на устройстве. Исходный файл всегда скачивается целиком. Объектные URL освобождаются при удалении и завершении работы пространства.

Иконка скачивания в заголовке редактора экспортирует сохранённую карточку в TXT: поля, статус, рейтинг и отметки неподтверждённых сведений. Несохранённые правки и вложения в этот файл не включаются.
## Запуск

Нужны Bun 1.4.2 и Node.js >=24. Из корня репозитория:

```sh
bun install --frozen-lockfile
./start.sh
```

`start.sh` запускает инфраструктуру, применяет миграции и заполняет демо (отключение seed: `SEED_DEMO_DATA=0`). Для запуска только UI/BFF при уже работающей локальной PostgreSQL создайте `nextjs_db`, настройте `DATABASE_URL_NEXTJS` в `apps/presentation-layer/.env` по примеру и выполните:

```sh
cd apps/presentation-layer
bun run db:migrate
bun run db:seed
bun run dev
```

Откройте [localhost:3000](http://localhost:3000). Для карточек, откликов и локальных навыков нужна PostgreSQL; Mastra требуется только для свободного чата. Docker Compose может запустить только базу: `docker compose -f docker-compose.dev.yml up -d postgres` из корня. Генерацию новых миграций выполняет владелец схемы командой `db:generate`; остальные применяют готовые SQL через `db:migrate`.

### Подключение чата к Mastra

В `apps/presentation-layer/.env` задайте `MASTRA_API_URL` (локально `http://localhost:4111`) и `MASTRA_CHAT_AGENT_ID` — ID уже зарегистрированного агента. После изменения перезапустите UI. Для Docker Compose ID задаётся в корневом `.env`. Ключ модели настраивается в `ai-logic-layer`.

Свободное сообщение отправляется через `POST /api/tasks/:id/chat` → `@mastra/client-js` → `agent.generate()`. Вход — `{messages: [{role: "user" | "assistant", content: string}]}`, выход — `{text: string}`. Передаются исходное описание задачи и переписка; ответ добавляется в текущую беседу. Пустой контекст пропускается; для длинных бесед передаются последние целые сообщения в пределах 96 КиБ. Вызов ограничен 30 секундами и не повторяется автоматически. При ошибке ввод остаётся в форме.

Это только транспорт: агент свободного чата должен быть отдельно настроен в `ai-logic-layer`. Без `MASTRA_CHAT_AGENT_ID` свободный чат возвращает `CHAT_NOT_CONFIGURED` (503); при недоступном агенте или неверном ответе — `CHAT_UNAVAILABLE` (502). Промпты, модели, инструменты, streaming и хранение истории в Mastra здесь не реализованы. Ответы на выбранные вопросы и навыки `@` продолжают использовать текущую локальную логику; документы в Mastra не отправляются.

## Показ за пять минут

1. В режиме бизнеса создайте черновик и опишите проблему своими словами. Ассистент покажет три уточняющих вопроса.
2. Нажмите на вопрос и отправьте ответ. Текст без изменений попадёт в выбранное поле карточки; неподтверждённый ответ пока не повышает оценку. Повторите для остальных вопросов.
3. Откройте «Карточка задачи», проверьте формулировки и отметьте подтверждение заполненных полей. Посмотрите сохранённую серверную оценку и нажмите «Подтвердить и опубликовать».
4. Переключитесь в режим студента. Найдите опубликованную задачу, выберите команду и нажмите «Откликнуться по критериям задачи». В подробной форме заполните решение, план, роли команды, срок, ссылку на репозиторий и ответы по критериям, затем отправьте отклик.
5. Вернитесь в режим бизнеса. Отклик появится справа: рассмотрите его, выберите команду или отклоните предложение. Выбор создаёт мэтч со стартовым пакетом и этапами. Можно выбрать несколько команд; отмена принятого решения не поддерживается.
6. В режиме студента откройте свой выбранный отклик и нажмите «Сдать этап». Укажите название выполненного этапа, ссылку на результат и что сделано. До подтверждения можно изменить результат; отправка сама по себе не приносит баллов.
7. В режиме бизнеса проверьте результат и вручную подтвердите этап. Команда получает 10 демонстрационных баллов за каждый подтверждённый этап. Повторное подтверждение возвращает конфликт и не начисляет баллы снова. В режиме студента проверьте статус и баллы.

Опубликованные задачи доступны для отклика при любой готовности. Низкая оценка помогает увидеть пробелы, но не блокирует публикацию или участие. Публикация и изменение публичной карточки требуют подтверждения текста бизнесом.

## Готовность задачи

Сохранённый рейтинг вычисляет канонический ADR-005 в `src/entities/task/model/score.ts`; история записывается в той же транзакции, что и изменение полей. UI показывает серверное значение и расшифровку. Для структурированных полей и трёх критериев приёмки используйте ссылку «Подробные поля и критерии приёмки» или `/task-match`.

Публикация независима от уровня рейтинга. Старые workspace-поля сохраняются миграцией; они не доказывают подтверждение всех канонических узлов задачи.

## API и данные

Все перечисленные маршруты реализованы; JSON-входы проверяются Zod. Ошибки: `{ "error": { "code": "...", "message": "..." } }`, при ошибке валидации дополнительно `fields`. Роли проверяются на сервере. Студент получает только опубликованные карточки с подтверждёнными полями и отклики выбранной команды. UI показывает загрузку, ошибку и повтор запроса, а формы сохраняют ввод при неудачной отправке.

| Метод и маршрут                      | Назначение                                                 |
| ------------------------------------ | ---------------------------------------------------------- |
| `GET /api/workspace`                 | Согласованный снимок `{tasks, teams, proposals, session}` |
| `GET /api/session`, `PATCH /api/session` | Текущие роль и команда, переключение демо-профиля |
| `GET /api/tasks`, `GET /api/tasks/:id` | Задачи с проверкой видимости |
| `POST /api/workspace/tasks`          | Создать черновик из описания                               |
| `PATCH /api/workspace/tasks/:id`     | Сохранить полную карточку с текущей `version`; `status: published` публикует после проверки подтверждений |
| `POST /api/tasks/:id/chat`           | Передать текстовую беседу настроенному агенту Mastra; доступно бизнесу |
| `GET /api/tasks/:id/score`           | Канонический рейтинг, уровень и `lines` по узлам ADR-005 |
| `GET /api/tasks/:id/score/history`   | Последние 100 сохранённых оценок для бизнеса |
| `GET /api/catalog` | Публичный каталог с фильтрами и сортировкой |
| `GET /api/teams`, `PATCH /api/teams/:id` | Профили команд |
| `GET /api/tasks/:id/proposals`, `POST /api/tasks/:id/proposals` | Список откликов / новый отклик выбранной команды |
| `POST /api/workspace/proposals/:id/decision` | Workspace-адаптер выбора/отклонения; `{status, note?}`, причина отклонения обязательна |
| `PUT /api/workspace/proposals/:id/milestone`   | `{title, resultUrl, comment}` — результат выбранной команды |
| `POST /api/workspace/proposals/:id/milestone/confirm` | Подтверждение результата, безопасное при повторе |
| `GET /api/proposals/:id/kickoff`     | Подтверждённые материалы, контакт и первый этап после выбора |
| `GET /api/teams/:id/progress`        | Подтверждённые результаты и баллы команды |

Канонические сущности: бизнес, задача, 17 узлов полей, grill-сессия и ходы, критерии, score events, команда, отклик, stages и swipes. Схема и миграции находятся в `src/shared/db`; общий рейтинг — ADR-005, рекомендации — ADR-006, решения и этапы — ADR-007. Workspace с девятью визуальными группами обращается к ним через `src/server/workspace` и `/api/workspace/*`. Подробный сценарий `/task-match` использует канонические маршруты напрямую.

Изменения карточки и история оценки фиксируются транзакционно; устаревшая версия возвращает `409`. Выбор создаёт стартовый пакет и этапы по подтверждённым критериям. Повторное подтверждение этапа не начисляет баллы; отмена принятого решения не поддерживается. Бизнес может выбрать несколько команд. Legacy workspace-данные сохранены в миграции и не считаются доказательством прохождения канонической прожарки.

Workspace snapshot рассчитан на объём демо. AI остаётся в `ai-logic-layer`/Mastra; BFF вызывает его через клиент, без прямых вызовов модели.

## Проверка

### Первое открытие

При первом открытии показывается короткая настройка: бизнес указывает название компании и необязательный логотип, студент выбирает существующую команду. Настройку можно снова открыть по `/onboarding`. Профиль компании хранится в PostgreSQL, выбранная роль и команда — в HTTP-only cookie. Это по-прежнему общее демо без регистрации и проверки членства в команде.

Видео слева воспроизводится по кругу и сохраняет исходное соотношение 3:4; форма занимает оставшуюся ширину и при необходимости пропорционально уменьшает видео. На экранах до 760 px видео скрыто и не загружается. При `prefers-reduced-motion` показан статичный кадр с возможностью включить видео вручную.

Логотипы PNG/JPEG/WebP до 2 МБ загружаются в RustFS через `POST /api/business-logos` и читаются через `GET /api/business-logos/:id`. Используются существующие `RUSTFS_ENDPOINT`, `RUSTFS_ACCESS_KEY`, `RUSTFS_SECRET_KEY`; для локального запуска хранилища: `docker compose -f docker-compose.dev.yml up -d rustfs` из корня. Без хранилища можно продолжить без логотипа. Перед запуском примените миграцию `20260923112428_onboarding_business_logo.sql` обычной командой `bun run db:migrate`.

`bun scripts/test-onboarding.ts` проверяет сохранение профиля, переключение ролей, обязательный выбор команды, подстановку компании в новые задачи и независимость метаданных задач. Требует сервер и БД; удаляет только созданные им записи.

Команды из `apps/presentation-layer`:

```sh
bun run check-types
bun run build
bun run lint -- src/_pages/workspace src/features/student-catalog src/features/team-picker src/features/task-editor src/features/task-inspector src/entities/workspace
bun test src
bun run test:backend
```

Старые `test:backend` и `test:onboarding` унаследованы из main; их соответствие объединённым контрактам не подтверждено. Проверки после последних слияний не запускались по просьбе пользователя. История ранее выполненных проверок и ограничения описаны в `../../docs/adr/2026-09-23-task-match-integration.md`.

Короткая проверка UI:

- В режиме бизнеса на широком экране видны три панели; на узком доступны задачи, чат и отклики через переключатели.
- В режиме студента виден каталог всех опубликованных задач по убыванию готовности, включая 25-балльную карточку. Чата нет; поиск, фильтры и «Мои отклики» работают вместе. Сведения и отклик открываются в боковой панели.
- Новый черновик показывает три вопроса; ответ сохраняется именно в выбранное поле.
- Без подтверждения поля не добавляют баллы, публичные изменения не сохраняются без проверки текста.
- Опубликованная задача с низкой оценкой доступна студенту; отправленный отклик виден бизнесу.
- Выбор, отклонение и отмена решения отражаются у студента; подтверждённый этап даёт ровно 10 баллов.
- Обновление рабочего пространства перечитывает БД без удаления сохранённых задач, команд и результатов. Переписка и незавершённый ввод остаются локальными; основные действия обращаются только к собственному API.
- В «Моя команда» смена профиля обновляет «Мои отклики» и баллы. Редактирование имени сохраняет отклики команды; создание произвольных команд не поддерживается. Форма требует название и 3–5 участников.
