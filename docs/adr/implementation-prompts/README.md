# Промпты реализации ADR

Откройте каждый файл в отдельном чате/агенте. Один промпт — одна feature-ветка и один worktree; интегрируйте изменения по очереди после review. Все ADR 002–010 имеют статус Proposed — команда должна согласовать решения перед реализацией. ADR-001 принят; его промпт просит в первую очередь сверить уже внесённую работу, чтобы не дублировать её.

## Рекомендуемый порядок

1. [ADR-001 — исправления безопасности зависимостей](001-dependency-security-fixes.md) — проверка/доделка уже принятого решения.
2. [ADR-002 — границы модулей и синхронный BFF](002-module-boundaries-sync-bff.md) — основание backend.
3. [ADR-003 — контракт AI-слоя](003-ai-layer-contract.md) — inference и интерфейс BFF.
4. [ADR-004 — прожарка и поля](004-grill-state-and-field-lifecycle.md).
5. [ADR-005 — рейтинг и история](005-deterministic-scoring-and-history.md).
6. [ADR-006 — рекомендации и каталог](006-recommendations-and-catalog.md).
7. [ADR-007 — отклики, мэтч и этапы](007-proposals-match-stages-points.md).
8. [ADR-008 — демо-роли и доступ](008-demo-roles-and-access.md).
9. [ADR-009 — REST-контракт BFF](009-bff-api-contract.md) — до параллельной реализации API-клиентов зафиксировать контракт.
10. [ADR-010 — приёмочная проверка](010-acceptance-verification.md) — после появления потоков, которые проверяет матрица.

Схема БД общая для нескольких ADR: назначьте одного владельца миграций и применяйте изменения последовательно. Не запускайте одновременно независимые миграции из worktree. Перед началом каждого следующего ADR интегрируйте предыдущий либо явно согласуйте базовую ветку и зависимости.
