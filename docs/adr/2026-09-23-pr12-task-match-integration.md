# Совмещение PR #12 с Task Match

Дата: 2026-09-23
Статус: интеграционные изменения; выполнение итогового сценария не проверено

## Контекст

По запросу пользователя интеграция PR #16 переносится в существующий PR #12
(`grill-me-agents`). Подготовка выполняется отдельно в worktree
`hack-task-match-pr12`, ветка `integration/pr12-task-match`. Исходный head #12:
`6942e3fc2330672caa9c7eb3822dcd3adfe2e5f0`; head #16 при начале работы:
`4f300f13f1bc9699c7901be2fda2aed5c00c663d`. Актуальный main — `b6df9de`.
Новый PR не нужен; состояние существующего PR #12 (не draft) не меняется.

Заметки в `2026-09-23-task-match-integration.md` и раннем описании #16 о
неподключённом PR #12 фиксируют предыдущий этап. После текущего совмещения
они не являются описанием окончательного состава ветки PR #12.

## Решение

- Включить Task Match из #16: канонические lifecycle, score/history, каталог,
  fit, отклики, kickoff, этапы и доступ. Сохранить актуальный frontend main,
  onboarding, логотипы, документы, голосовой ввод и оформление.
- Свести AI-реализацию #12 с ADR-002/003: состояние бизнес-сценария находится
  в Next.js BFF/`nextjs_db`; Mastra выполняет stateless inference через
  `analyze-text` и `phrase-question`.
- Использовать полезные промпты #12 в согласованном AI-контракте. Stateful
  suspend/resume сценарий не служит вторым владельцем прожарки. LLM не вычисляет
  канонический рейтинг и не выбирает команду: score и fit остаются кодом BFF.
- UI и BFF обращаются к Mastra через `@mastra/client-js` и `MASTRA_API_URL`.
  Свободный чат является отдельной возможностью и использует настроенный
  `MASTRA_CHAT_AGENT_ID`; он не подтверждает поля и не меняет рейтинг сам.

## Проверки и ограничения

По действующему запросу пользователя новые тесты не запускаются. Результаты,
перечисленные в прежней заметке интеграции, получены до последующих merge и
не подтверждают эту ветку. Live Mastra, ответы модели, задержки, корректность
итоговой регистрации агентов и полный UI → BFF → Mastra сценарий не проверены.

Миграции и ограничения legacy-данных наследуются из #16. История main включает
onboarding и миграцию `20260923113557_task_match_integration`; её наличие не
означает выполнения на целевой БД. Нельзя выдавать сохранённые старые девять
UI-групп за семнадцать подтверждённых узлов канонического рейтинга.

Владелец следующего этапа проверяет итоговые env/регистрацию Mastra, маппинг
владельцев legacy-задач и миграции, затем отдельно выполняет приёмку на итоговом
commit. Ограничения незавершённого ADR-009 и отсутствие отдельного ADR-010 PR
сохраняются; полное соответствие всем ADR не заявляется.
