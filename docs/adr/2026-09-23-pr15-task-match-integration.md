# Совмещение PR #15 с PR #12

Дата: 2026-09-23

## Контекст

По запросу пользователя PR #12 включается в существующую ветку PR #15
`feat/adr-009-bff-api-contract`. Подготовка выполняется в отдельном worktree
`hack-task-match-pr15`, ветка `integration/pr15-task-match`; другие worktree
не меняются. Исходный head #15 — `487776fc0377c4440a1ab048cf85ef2b94875e2e`,
включаемый head #12 — `3b0d02792c6564cc8c3e9de933a008a29481d744`.

PR #12 уже содержит интеграцию Task Match из #16 и актуальный main, включая
onboarding, логотипы, документы, голосовой ввод и тему. На момент проверки
GitHub оба PR OPEN, PR #15 не draft, его список checks пуст. Новый PR не
создаётся и состояние существующего PR не меняется.

## Решение

- Сохранить канонические DB/use-case/UI из интеграции #12. Реальные задачи,
  поля, версии, score/history, каталог, fit, отклики и этапы хранятся в
  `nextjs_db` и изменяются через общие транзакционные операции.
- Совместить полезный слой ADR-009 — общие Zod-контракты, тонкие handlers и
  единые ошибки — с этими операциями. Не включать второй Map/globalThis backend,
  повторный расчёт score/fit, actor-заглушку или отдельный AI-порт прототипа.
- Сохранить действующие DTO frontend и BFF, проверки роли/владельца, фильтрацию
  неподтверждённых полей и существующую семантику ошибок. Входная валидация
  возвращает 422, нарушение схемы серверного ответа — 500; русские сообщения
  не раскрывают внутренние ошибки провайдера или данные соединения.
- Сохранить stateless `analyze-text` и `phrase-question` из PR #12. Inference
  выполняется вне DB-транзакции; запись сформулированного вопроса сверяется с
  текущими версией, узлом и неотвеченным ходом. AI не назначает рейтинг или мэтч.
- История миграций наследуется из PR #12; отдельная конкурирующая схема для
  контрактов ADR-009 не вводится.

## Проверки и границы результата

По просьбе пользователя новые тесты не запускаются. В исходном описании PR #15
указаны 22 успешных теста, typecheck и lint прототипа на in-memory runtime;
это исторические результаты до текущего merge. Они не подтверждают работу
итоговых маршрутов, Drizzle-транзакций, миграций или live Mastra. Предыдущие
результаты #16 и #12 также не переносятся на новый commit автоматически.

Не заявляется проверка live модели, полного UI → BFF → Mastra сценария,
чистой установки и upgrade заполненной БД. Ограничения legacy ownership и
преобразования старых UI-групп в канонические поля наследуются из #12/#16.
Следующий владелец просматривает итоговые контракты/маршруты и миграции, затем
отдельно выполняет приёмку на итоговом commit. Старый `tests/api.test.ts` перенесён в
`tests/legacy/adr009-prototype.ts.disabled`: он зависит от удалённого Map-runtime
и не является доказательством приёмки действующего backend.

Обновление задачи, её полей, версии и score/history теперь выполняется в одной
Drizzle-транзакции. Ответы маршрутов проходят проверку общей схемой после
JSON-нормализации дат. Зависимости установлены через frozen lockfile; выполнен
`git diff --check`. Тесты, typecheck, lint и build не запускались.
