# Architecture Decision Records

Решения по архитектуре MVP «Мэтч задач». Источники: [ТЗ](../TASK_MATCH_MVP_SPEC.md),
[описание платформы](../TASK_MATCH_PLATFORM.md), [архитектура](../ARCHITECTURE.md),
[AGENTS.md](../../AGENTS.md). Шаблон: [template.md](template.md).

ADR 002–010 имеют статус **Proposed**: это предложения, которые команда ещё не
согласовала, и владельцы не назначены. На момент написания код приложения —
заготовка: в Mastra нет агентов, в `nextjs_db` есть только таблица `users`,
workers содержит `example-queue`. Всё, что описано ниже, пока не реализовано.

## Вопросы для команды

1. Согласовать ADR 002–010 или отклонить их. Назначить ответственных за backend, AI, UI и схему БД. Владелец схемы генерирует единую миграцию.
2. C-2: общий дедлайн хода, 20 с или жёстче?
3. C-4 и C-7: какой сценарий показываем на демо? Порядок блоков; как дойти до 92 % (прожарка до 77, seed-задача или отклик из каталога).
4. C-5, C-6: правила однократных баллов и видимости контакта.
5. Какой метод `@mastra/client-js` 1.47 запускает workflow? Работают ли строки моделей `anthropic/…` и `openai/…` в установленной `@mastra/core` без новых зависимостей? В `.env.example` нет `ANTHROPIC_API_KEY`, `LLM_MODEL`, `CLASSIFIER_MODEL`, `AI_ENABLED`.
6. Нужно ли T-1 давать эталонные 24 → 44 → 59 при `AI_ENABLED=false` (детерминированная заглушка) или допускается ручная правка полей?
7. Мелкие правила без ответа в ТЗ:
   - направление сортировки по дате (FR-4.4);
   - убирает ли ↑ задачу из колоды;
   - как считать N в «ещё N задач»;
   - правка отклика в `on_hold`;
   - выбор команд после `in_work` и закрытие из `in_work`;
   - число бизнесов в seed.
8. Нужен ли `apps/workers` в демо? По ADR-002 изменений в нём нет.
