# ADR-011: Интерактивный чат менеджера через Mastra `task-manager-agent`

Date: 2026-09-23
Status: Proposed
Owner: team

## Context

Рабочее пространство бизнес-роли («Чат по задаче», `WorkspacePage`) — главная
точка менеджера, создающего и уточняющего задачи. До этого ассистент отвечал
только детерминированными локальными строками: `runChatSkill` для четырёх
навыков (@-меню) и захардкоженный текст для свободного ввода. Фидбек по
дизайну: «используй mastra-клиент и сделай часть менеджера — создателя задач —
интерактивной за счёт работы с apps/ai-logic-layer».

Ограничения стека (AGENTS.md, [ADR-003](003-ai-layer-contract.md),
[ADR-009](009-bff-api-contract.md)):

- inference только в `ai-logic-layer`; UI обращается к Mastra через
  `@mastra/client-js` и `MASTRA_API_URL`;
- сбой AI не должен ронять демо (NFR: работа без внешнего AI);
- демо-данные карточки живут в памяти вкладки, в `nextjs_db` их нет — BFF не
  может прочитать карточку сам;
- один memory-thread на задачу — история диалога нужна агенту для контекста.

## Decision

1. **Новый агент `task-manager-agent`** (`apps/ai-logic-layer/src/mastra/agents/task-manager-agent.ts`,
   регистрация в `src/mastra/index.ts`): интерактивный ассистент роли бизнеса.
   Вход — переданный BFF свежий снимок карточки (сводка полей, балл,
   расшифровка, отклики команд) плюс навык/текст сообщения. Инструкции
   запрещают агенту выдумывать факты о бизнесе, менять/публиковать карточку и
   выбирать команду; вывод — plain text (UI не рендерит markdown). Память —
   общий `sessionMemory`, thread = `${sessionId}:${taskId}`.
2. **BFF-маршрут `POST /api/assistant`** (`app/api/assistant/route.ts` — тонкий
   re-export, логика в `src/shared/api/assistant-route.ts`): zod-валидация
   контракта `src/shared/api/contracts/assistant.ts` (400/422 с форматом ошибки
   ADR-009), вызов `askTaskManagerAgent()` (`src/shared/api/mastra.ts`) с
   таймаутом 15 с через `AbortSignal`.
3. **Хардкод ответов чата вырезан полностью** (решение команды): `runChatSkill`
   и все локальные заглушки удалены, ветка `field` тоже отвечает через агента
   (мутация поля остаётся локальной, реплика — от Mastra). Контекст строит
   чистая функция `buildAssistantContext()`
   (`src/entities/workspace/assistant.ts`). Если Mastra недоступна, UI
   показывает честное сообщение об ошибке («Ассистент сейчас недоступен…»)
   с предложением повторить, а не выдуманный ответ.
4. **Ответ в поле карточки (мутация) остался локальным** — интерактивность
   касается только реплик ассистента; данные по-прежнему пишет UI.

## Alternatives

- **Вызов `agent.generate` напрямую из клиентского компонента** — проще, но
  выставляет `MASTRA_API_URL` браузеру и обходит BFF-контракт ADR-009.
  Отклонено.
- **Существующий `task-evaluator-agent`** — его контракт строгий raw JSON
  (RatingReport), формат не подходит для диалога. Отклонено.
- **Полный отказ от локальных ответов** — при недоступной Mastra чат
  показывает сообщение об ошибке. Принято: хардкод вырезан по решению
  команды («все чаты — на Mastra»), fallback-строки удалены.

## Consequences

- (+) Чат менеджера отвечает по фактическим данным карточки и откликов, с
  историей диалога в memory-thread.
- (+) Ни одного локального ответа ассистента: все реплики (включая ветку
  ответа в поле) генерирует `task-manager-agent`.
- (−) При недоступной Mastra чат честно сообщает об ошибке — на время сбоя
  демо-диалог невозможен (осознанный обмен на отсутствие хардкода).
- (−) Контекст карточки передаётся каждым ходом запросом (демо-данные не в
  БД) — при переходе на персистентные задачи источник контекста меняется на
  чтение из `nextjs_db` в BFF.
- (−) Ответ ассистента не потоковый (одним `generate`) — индикатор
  «печатает…» вместо стриминга; при желании заменяется на `stream`.

## Verification

- `bun run check-types` (turbo, 3 пакета) и `bun test` (контракты, контекст,
  парсеры флоу) зелёные;
- live: `POST /api/evaluate` → `200` с `RatingReport` (score/level/verdict/
  breakdown), невалидный запрос → `422`;
- live: `POST /api/grill` start → `suspended` с вопросами SMART-раунда,
  resume с answers → следующий suspend (follow-up раунд). Полный прогон до
  `success` вживую не гонялся (дорого по LLM), ветка покрыта контрактным
  нормализованием `suspended → step → resumeData`;
- **Попутно исправлен баг воркфлоу**: `PipelineState.draft: z.unknown()` в zod 4
  требует presence ключа, а JSON-снапшот теряет `draft: undefined` — resume
  падал с «Step input validation failed». Стало `z.unknown().optional()`.

## Сценарий использования (мэнеджер в чате)

1. Создание черновика → авто-вызов `POST /api/evaluate` → рейтинг в чате и
   бейдж в шапке карточки.
2. @-меню → «Запустить прожарку» → `POST /api/grill` (start) → воркфлоу
   `stack1-result-control` задаёт вопросы стадиями; ответы бизнеса идут в
   resume (парсер ответов/языков — `chat-flow.ts`).
3. `success` → `applyGrillPackage` заполняет и подтверждает поля карточки →
   автоматический повторный `POST /api/evaluate` (пересчёт «было → стало» в
   том же thread оценщика).
4. @-меню → «Оценить задачу» — внеочный пересчёт; публикация из карточки
   не блокируется рейтингом (rating — опциональное поле Task).
