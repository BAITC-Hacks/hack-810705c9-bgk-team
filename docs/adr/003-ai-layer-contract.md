# ADR-003: Контракт AI-слоя: агенты Mastra, проверки, таймауты и fallback

Дата: 2026-09-23
Статус: Proposed
Владелец: не назначен

## Контекст

ТЗ задаёт три агента: `griller`, `card-extractor` и `classifier` на `openai/gpt-5.4-nano` (AI-1, AI-4).
Кроме того, ТЗ требует:

- два workflow, `analyze-draft` и `grill-turn` (AI-2, AI-3);
- ответы в JSON по zod-схемам (AI-5);
- обязательный `source_quote` (AI-6, AI-10);
- фильтр цифр в вариантах ответа (AI-7);
- один повтор при невалидном JSON (AI-8);
- таймауты 15 с для основной модели и 5 с для nano (AI-9);
- запрет на рейтинг и выбор команды (AI-12);
- отсутствие персональных признаков во входе агентов (AI-13);
- журнал `AiLog` (AI-14);
- работу без внешнего AI (NFR-5, T-13, T-15).

Промпты и схемы `GrillQuestion`, `Extraction`, `Classification` приведены в платформе,
разделы 8.3–8.7. Проверки описаны в разделе 8.6.

[ADR-002](002-module-boundaries-sync-bff.md) оставляет решения и состояние в BFF. В
`ai-logic-layer` пока нет ни одного агента. Пакетов провайдеров в
`ai-logic-layer/package.json` нет. В `.env.example` нет `ANTHROPIC_API_KEY`,
`LLM_MODEL`, `CLASSIFIER_MODEL` и `AI_ENABLED`, есть только `OPENAI_API_KEY`.

## Решение

1. **Агенты** регистрируются в `ai-logic-layer/src/mastra/agents/*` с промптами из
   платформы (8.3, 8.7). Модели берутся из `LLM_MODEL` и `CLASSIFIER_MODEL`, а
   значения по умолчанию из документа нужно сверить с model router установленной
   `@mastra/core`.
2. **Два stateless workflow** вместо одного `grill-turn` с шагом `decide`:
   - `analyze-text`: `classify` (nano) параллельно с `extract` (`card-extractor`), затем guards.
     Вход: `{ text, targetNodes[], dictionary: {roles, skills} }`.
     Выход: `{ nodes: [{node, covered, evidence, specificity}], fields: [{node, value, source_quote, specificity}], roles[], skills[], log }`.
     Используется и для черновика (`targetNodes` = все 17 узлов), и для ответа в ходе прожарки.
   - `phrase-question`: `griller` → guards. Вход: `{ node, isPushback, context: string }`.
     Выход: `{ question, options[], target, is_pushback, log }`.

   BFF выполняет логические шаги AI-2/AI-3 так: `analyze-text` → `decide`
   (код BFF, [ADR-004](004-grill-state-and-field-lifecycle.md)) → `phrase-question`.
   Классификация и извлечение идут параллельно, потому что обе работают по
   одному тексту. Это укладывает ход в бюджет из п. 5.
3. **Guards в Mastra** (платформа 8.6):
   - zod-валидация с одним повтором;
   - `source_quote` и `evidence` проверяются как подстрока входного текста после
     нормализации регистра, пробелов и пунктуации;
   - `options` с цифрами отбрасываются;
   - если `target` не равен запрошенному узлу, возвращается `ok:false`;
   - роли и навыки вне справочника отбрасываются.

   Каждый отброшенный элемент попадает в `log.dropped`.
4. **BFF повторно проверяет цитату** по тексту, который он сам сохранил (ответ или
   черновик), прежде чем записать `Field`. Нормализатор — маленькая чистая функция,
   которая намеренно дублируется в двух приложениях. Авторитетна проверка BFF, так
   как только он знает исходный текст хода.
5. **Таймауты и fallback.** Mastra ограничивает вызов агента 15 с (основная
   модель) и 5 с (nano). Повтор при невалидном JSON укладывается в тот же лимит.
   BFF задаёт общий дедлайн хода через `AbortSignal` (предлагается 20 с, см. вопросы).
   Если BFF получил ошибку, таймаут, `ok:false` или `AI_ENABLED=false`:
   - вместо `phrase-question` берётся шаблонный вопрос узла с шаблонными
     вариантами из дерева прожарки в BFF;
   - вместо `analyze-text` работает заглушка на правилах в BFF: регулярки для
     чисел, периодов, URL, email и ключевых слов узла. Для целевого узла весь
     ответ становится значением поля, а цитатой служит весь ответ, поэтому
     AI-6 выполняется тривиально.

   Сценарий продолжается при любом сбое: `fallback_used = true`, причина пишется в журнал.
6. **`AI_ENABLED` читает BFF.** При `false` Mastra не вызывается вообще, поэтому
   T-15 не зависит от доступности `ai-logic-layer`.
7. **AI-13.** Во вход агентов идёт только текст бизнеса (черновик и ответы) и
   справочник. Данные команд (профиль, отклики) в Mastra не передаются: `fit`
   считает код.
8. **`AiLog` хранится в `nextjs_db`, запись делает BFF.** Mastra возвращает в
   `log` поля `kind`, `agent`, `model`, `prompt`, `input`, `raw_output`,
   `parse_ok`, `retry_count`, `dropped[]`, `latency_ms` и `error?`. BFF добавляет
   `task_id`, `turn_id?`, `fallback_used`, `fallback_reason` и `created_at`.
   Ключи, заголовки и env в журнал не попадают. Трейсы Mastra в `mastra_db`
   остаются служебными и в UI не показываются. Доступ к журналу описан в
   [ADR-008](008-demo-roles-and-access.md).

## Альтернативы

- **Один workflow `grill-turn` с `decide` внутри Mastra**, как в AI-3. Для этого
  нужно дерево прожарки в Mastra: либо дублирование, либо общий пакет (ADR-002).
  Кроме того, Mastra должен знать состояние сессии из `nextjs_db`. Отклонено для
  MVP.
- **Вызов агентов из BFF по одному** через `getAgent().generate()`. Так проще, но
  guards, повтор и лимиты размазываются по BFF, а в AI-слое остаётся голый
  inference. Отклонено: проверки ответа модели — ответственность AI-слоя.
- **Fallback внутри Mastra.** Не закрывает сценарий «Mastra недоступен» и
  требует переносить шаблоны узлов в AI-слой. Отклонено. Шаблоны и заглушка
  относятся к дереву прожарки BFF.
- **`AiLog` в `mastra_db`** с чтением через Mastra API. Отклонено: журнал привязан
  к задаче и ходу в `nextjs_db`, а показывать его пришлось бы через второй сервис без joins.

## Последствия

- Плюс: T-12, T-13, T-14 и T-15 проверяются детерминированно, если подменить
  ответ Mastra или отключить AI.
- Плюс: при сбое AI сценарий деградирует до шаблонов, а не падает.
- Минус: нормализатор цитат живёт в двух местах, их нужно синхронизировать.
- Минус: логическая форма AI-2/AI-3 распределена между модулями, в README
  нужна схема хода.
- Риск: в худшем случае ход длится `max(5, 15) + 15` с ≈ 30 с и больше, что
  противоречит NFR-6 (≤ 5 с). Дедлайн BFF обрезает хвост и включает шаблон.
  Цель NFR-6 достижима только при быстрых моделях.
- Риск: заглушка на регулярках не повторит эталонные рейтинги Приложения А
  (24 → 44 → 59) при `AI_ENABLED=false` (см. [ADR-010](010-acceptance-verification.md)).

## Затронутые модули и проверка

- `apps/ai-logic-layer/src/mastra/{agents,workflows,lib}`: агенты, 2 workflow, guards.
- `apps/presentation-layer/src/shared/api/mastra.ts`: клиент, дедлайн, флаг.
  Дерево прожарки и заглушка лежат в `src/entities/grill`, запись `AiLog` — в
  `src/entities/ai-log`.
- env: `ai-logic-layer/.env.example` получает `ANTHROPIC_API_KEY`,
  `OPENAI_API_KEY`, `LLM_MODEL`, `CLASSIFIER_MODEL`. `presentation-layer/.env.example`
  получает `AI_ENABLED`. Значения не коммитятся.
- Проверка: T-12, T-13, T-14 и T-15 через подменённый клиент Mastra в BFF. Один
  живой прогон `analyze-text` на эталонном черновике через Mastra Studio (:4111)
  с просмотром `log.dropped`. Живой прогон отчитывается отдельно от мок-проверок.

## Допущения и открытые вопросы

- Какой именно метод `@mastra/client-js` 1.47 запускает workflow и ждёт результат?
  Проверить по установленному пакету до разработки.
- Поддерживает ли model router установленной `@mastra/core` строки
  `anthropic/claude-sonnet-5` и `openai/gpt-5.4-nano` без отдельных провайдерных
  пакетов? Если нет, нужно добавлять зависимости (вне объёма этого ADR).
- Общий дедлайн хода: 20 с или жёстче ради NFR-6? Требует решения команды.
- Задача классификатора (AI-4) — предлагать роли и навыки. Платформа (раздел 11)
  говорит, что «стек и роли ИИ не угадывает». Предлагается компромисс:
  классификатор предлагает теги только при наличии цитаты-доказательства, а
  бизнес подтверждает список (FR-2.7).
