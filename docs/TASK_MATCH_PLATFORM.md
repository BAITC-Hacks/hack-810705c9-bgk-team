# «Мэтч задач»: подработка и практика для студентов на реальных бизнес-задачах

MVP для хакатона AI Sana: 5 часов, 3–5 человек. LLM — Mastra: Claude формулирует и извлекает, OpenAI GPT-5.4 nano классифицирует.

## 1. Суть

### Проблема

| Сторона | Проблема |
|---|---|
| Студенты | Нет доступа к реальной подработке и практике. Задания от бизнеса размытые: непонятно, что сделать, с какими данными и как примут работу |
| Бизнес | Задачи не решаются из-за нехватки рук. Бизнес не умеет ставить задачу исполнителю |

### Решение

Платформа связывает бизнес-задачи со студенческими командами специалистов: разработчиков, аналитиков, дизайнеров, ML- и QA-инженеров.

| Сторона | Что получает |
|---|---|
| Студенты | Подработку или практику на реальной задаче. Грамотное задание: цель, данные, критерии приёмки, контакт. Портфолио подтверждённых результатов с отзывом бизнеса |
| Бизнес | Решение своей задачи. Помощь в постановке задачи через прожарку. Выбор из нескольких команд |

### Как работает

1. Бизнес пишет черновик задачи и выбирает формат: подработка, практика или оба.
2. ИИ задаёт вопросы исполнителя по одному («прожарка»), ответы заполняют карточку, рейтинг 0–100 растёт.
3. Задача публикуется в каталоге и в колодах команд с подходящими ролями и навыками.
4. Команда выбирает задачу и отправляет отклик.
5. Бизнес выбирает команду — мэтч. Команда получает стартовый пакет.
6. За подтверждённый этап команда получает баллы.

**Рейтинг = качество задания для студента: доля вопросов первого дня команды, на которые бизнес ответил конкретно и подтвердил ответ.**

### Формат работы

| Формат | Что получает студент | Поле карточки |
|---|---|---|
| Подработка | Оплата — условия пишет бизнес (за этап, за проект) | `engagement = paid`, `compensation_note` |
| Практика | Задача для учебной практики, подтверждённые этапы и отзыв бизнеса для отчёта | `engagement = practice` |
| Оба | Команда выбирает | `engagement = both` |

- Формат выбирает бизнес на шаге черновика.
- Формат **не влияет на рейтинг**: рейтинг оценивает качество задания, а не размер оплаты.
- Команда указывает, что ищет: подработку, практику или оба. Колода показывает задачи подходящего формата, каталог — все.
- Платежи, договоры и документы вуза — вне MVP.

### Правила кейса

| Правило | Решение |
|---|---|
| Рейтинг ≠ популярность | Баллы только за подтверждённые поля. Лайки, отклики, мэтчи в формулу не входят |
| Задачи не скрываются | Каталог показывает все опубликованные задачи |
| Нет автоназначения | Мэтч — только ручное решение бизнеса. ИИ сортирует отклики, не скрывает |
| Нет баллов за количество | Нет баллов за отклики, свайпы, длину текста |
| ИИ не выдумывает | Поле = слова бизнеса + цитата-источник, цитату проверяет код. Варианты ответа — только формат, без цифр |
| Человек подтверждает | Поле от ИИ даёт 0 баллов до подтверждения |
| Без персональных признаков | Совпадение считается по ролям, навыкам и интересам команды |

## 2. Сценарий

Регистрации нет — переключатель роли в шапке.

| # | Шаг | Что происходит | Состояние |
|---|---|---|---|
| 1 | Черновик | Бизнес пишет 2–3 предложения, система разбирает их | `Task: draft` |
| 2 | Прожарка | Вопросы исполнителя по одному, максимум одно уточнение на узел | `GrillSession: active` |
| 3 | Карточка | В конце блока — сводка «Верно?», ответ «Верно» подтверждает поля | `Field: suggested → confirmed` |
| 4 | Рейтинг | Чек, следующий шаг, «было → стало» | вычисляется |
| 5 | Публикация | «Подтвердить и опубликовать»: неподтверждённые поля не публикуются. Разрешена при любом рейтинге | `Task: published` |
| 6 | Отклик | Колода задач под роли и навыки команды, свайп → открывает форму отклика | `Proposal: submitted` |
| 7 | Решение | Бизнес выбирает или отклоняет с причиной | `Proposal: accepted / rejected` |
| 8 | Старт | Команда получает стартовый пакет: материалы, контакт, первый этап | `Task: in_work` |
| 9 | Прогресс | Критерии становятся этапами, бизнес подтверждает этап, команда получает +10 | `Stage: confirmed` |

## 3. Рейтинг

### 3.1. Узлы: 7 блоков, 17 узлов, 100 баллов

Каждый узел — вопрос, который исполнитель задаёт в первый день.

| Блок | Узел | Вопрос исполнителя | Баллы | Условие |
|---|---|---|:-:|---|
| Контекст (20) | `context.current` | Как процесс устроен сейчас? | 5 | заполнено |
| | `context.size` | Насколько велика проблема? | 5 | есть число |
| | `context.change` | Что должно измениться? | 10 | заполнено |
| Данные и материалы (20) | `data.what` | Какие данные, API, документация? | 10 | заполнено |
| | `data.volume` | Объём, период? | 5 | есть число или период |
| | `data.sample` | Пример, схема, Swagger? | 5 | ≥3 строк таблицы или URL |
| Результат (15) | `result.artifact` | Что сдаём: сервис, бот, модель, макет, отчёт? | 10 | выбран тип и есть описание |
| | `result.acceptance` | Как сдаём: демо, репозиторий, документация? | 5 | заполнено |
| Критерии (15) | `criteria.items` | По каким метрикам примете работу? | 5 × 3 | метрика + порог с числом = 5; без числа = 2 |
| Ограничения (10) | `constraints.deadline` | Срок? | 4 | есть дата или срок |
| | `constraints.stack` | Стек, интеграции, нужные роли? | 3 | подтверждены `needed_roles` и `needed_skills` |
| | `constraints.other` | Иные границы: что нельзя, конфиденциальность? | 3 | заполнено, «нет» засчитывается |
| Пользователи (10) | `users.role` | Кто пользователь решения? | 5 | заполнено |
| | `users.scale` | Сколько их, в какой ситуации? | 5 | заполнено |
| Связь (10) | `link.contact` | Кому писать? | 4 | email или мессенджер |
| | `link.cadence` | Как часто консультации? | 3 | заполнено |
| | `link.response` | Когда ответите на отклики? | 3 | число дней |

«Заполнено» = поле в состоянии `confirmed`.

### 3.2. Правила

- Баллы считает функция `score(card)`, без ИИ.
- Правка поля возвращает его в `suggested`, баллы снимаются до повторного подтверждения.
- Ответ «нет / не применимо» даёт 0 баллов. Исполнители видят его на карточке вместо «неизвестно».
- Каждое изменение рейтинга пишется в `ScoreEvent`.

```ts
export function score(card: Card) {
  const lines = NODES.map((node) => {
    const f = card.fields[node.id];
    const ok = f?.state === "confirmed" && !f.notApplicable;
    return { node: node.id, points: ok ? node.rule(f) : 0, reason: ok ? node.explain(f) : "нет ответа" };
  });
  return { total: sum(lines.map((l) => l.points)), lines };
}
```

### 3.3. Уровни

| Рейтинг | Уровень | Для исполнителя | Каталог | Колоды |
|---|---|---|---|---|
| 0–39 | Черновик | Старт только после уточнений | Пометка «требует уточнения» | Нет |
| 40–69 | Рабочая | Можно начать, часть вопросов открыта | Да | Да |
| 70–89 | Готовая | Можно начать сразу | Выше в сортировке | Да |
| 90–100 | Приоритетная | Полное ТЗ | Выделена | Отметка «Полностью готова» |

### 3.4. Интерфейс рейтинга для бизнеса

- **Чек**: строка на узел с причиной («0/15 Критерии: нет порога»), клик открывает поле.
- **Следующий шаг**: самый весомый открытый узел и последствие («+15 → Рабочая»).
- **Было → стало**: баллы, уровень, место после каждого подтверждения.
- **Вид исполнителя**: переключатель показывает карточку так, как её видит команда.

Код собирает пакет из подтверждённых полей по шаблонам, без LLM:

| Поле | Пункт стартового пакета |
|---|---|
| `data.sample` | Изучить материалы: ссылка |

## 5. Прожарка

Основа — skill [grill-me](https://github.com/mattpocock/skills). ИИ играет тимлида студенческой команды: спрашивает то, без чего исполнитель не начнёт работу.

### 5.1. Правила

- Один вопрос за раз. Следующий узел выбирает код. Минимум 3 вопроса за прожарку.
- Варианты ответа — только формат («выгрузка CSV · документация API · пример данных · данных нет»), без значений и цифр.
- Прожарка не спрашивает о доступах к системам бизнеса (стенды, ключи, учётные записи). Команда работает на выгрузках, примерах и документации.
- Узел, закрытый черновиком или прошлым ответом, пропускается.
- На расплывчатый ответ — одно уточнение («"Довольны" — как это измерить?»).
- В конце блока — сводка из цитат и вопрос «Верно?».
- Кнопка «Перейти к публикации» доступна всегда.

### 5.2. Порядок и ветки

```
Потребность → Результат → Критерии приёмки → Данные и материалы → Стек и роли → Пользователи → Связь
```

- `data.what = «данных нет»` → вопрос «Кто соберёт и за какой срок?»; `data.volume`, `data.sample` пропускаются.
- `result.artifact = «бот»` → вопрос «Какой мессенджер? Есть ли API для интеграции?» → `constraints.stack`.
- `result.artifact = «модель»` → вопрос «Есть размеченные данные?» → `data.what`.
- `result.artifact = «макет»` → вопрос «Есть брендбук?» → `data.sample`.

### 5.3. Ход

```
1. код    — следующий открытый узел
2. LLM    — вопрос + варианты формата          (ошибка → шаблон узла)
3. бизнес — отвечает
4. nano   — какие узлы закрыты, конкретно ли    (ошибка → заглушка)
5. LLM    — ответ → поля с цитатами; код проверяет цитаты
6. код    — расплывчато и уточнения не было → уточнение, иначе поле = suggested
7. код    — конец блока → сводка → «Верно?» → confirmed → пересчёт
```

```
│ Блок 3/7 · Критерии приёмки        ││ Контекст        ✓ 15/20       │
```

## 6. Выбор и мэтч

### 6.1. Профиль команды

`roles[]` (backend, frontend, bot, data, ml, design, qa), `skills[]`, `technologies[]`, `interests[]`, `looking_for` (paid | practice | both). Без персональных данных участников.

### 6.2. Совпадение

```ts
const share = (need: string[], have: string[]) =>
  need.length ? need.filter((x) => have.includes(x)).length / need.length : 0;

export function fit(team: Team, task: Task) {
  const value =
    0.5 * share(task.neededRoles, team.roles) +
    0.3 * share(task.neededSkills, [...team.skills, ...team.technologies]) +
    0.2 * (team.interests.includes(task.topic) ? 1 : 0);
  return { value, missing: task.neededSkills.filter((s) => !team.skills.includes(s)) };
}
```

Команда видит: «92%: роли backend и бот-разработка есть; Python, REST API, Telegram Bot API есть; не хватает: Docker».
Пустые `neededRoles` → задача только в каталоге, бизнесу подсказка «+3 и попадание в колоды».

### 6.3. Рекомендации команды: колода или сетка

- Условие: `published`, рейтинг ≥ 40, совпадение ≥ 0,5, формат совпадает с `looking_for` команды.
- Сортировка: `0.7 × fit + 0.3 × rating / 100`.
- Два вида одних и тех же рекомендаций, переключатель «Колода / Сетка». Выбор хранится в cookie.

#### Колода

- Одна карточка за раз, свайпы.
- Колода кончилась → «В каталоге ещё N задач →».

| Жест | Действие |
|---|---|
| → | Форма отклика |
| ← | Убрать из своей колоды (каталог и рейтинг не меняются) |
| ↑ | «Не хватает сведений»: блок + фраза; бизнес видит счётчик по блокам |

Клавиши ← → ↑ дублируют жесты.

#### Сетка

```
┌──────────────────────┐ ┌──────────────────────┐ ┌──────────────────────┐
│ Бот статусов доставки│ │ Сервис заявок        │ │ Дашборд посещаемости │
│ ЛогистикаПро         │ │ ЗаводМет             │ │ Колледж №5           │
│ 92% · Готовая 77     │ │ 71% · Рабочая 58     │ │ 55% · Приоритет 91   │
│ backend · bot        │ │ backend · frontend   │ │ data · frontend      │
│ Подработка           │ │ Практика             │ │ Оба                  │
│ ? срок, ограничения  │ │ ? данные             │ │                      │
│ [Откликнуться] [×] [?]│ │ [Откликнуться] [×] [?]│ │ [Откликнуться] [×] [?]│
└──────────────────────┘ └──────────────────────┘ └──────────────────────┘
```

- Плитка: название, компания, совпадение, уровень и рейтинг, нужные роли, формат, «Пока неизвестно».
- Кнопки на плитке = жесты колоды: «Откликнуться» (→), «Не сейчас» (←), «Не хватает сведений» (↑).
- Сортировка по умолчанию — как в колоде; можно переключить на «по совпадению» или «по рейтингу».
- Клик по плитке открывает карточку исполнителя.

### 6.4. Каталог

Все опубликованные задачи сеткой, сортировка по рейтингу, фильтры по теме, уровню, роли и формату.

### 6.5. Отклик

- Поля: техническое решение, план по этапам, роли в команде, срок, ссылка на прототип или репозиторий (необязательно).
- Для каждого критерия приёмки — «как проверим».
- Количество откликов не ограничено.

### 6.6. Колода бизнеса

- Только отклики на свою задачу, сортировка по совпадению. Низкое совпадение — в конец с пометкой, не скрывается.
- Рядом таблица «критерии × команды».

| Жест | Действие |
|---|---|
| → | Подтверждение «Команда получит ваш контакт» → мэтч |
| ← | Отклонить, причина обязательна: роли, стек, сроки, план, другое |
| ↑ | Отложить |

- Можно выбрать несколько команд или закрыть задачу без выбора.
- Экран мэтча: команда × задача → стартовый пакет.

## 7. Прогресс команды

- При мэтче критерии приёмки фиксируются и становятся этапами.
- Команда сдаёт этап: ссылка на демо или репозиторий и комментарий.
- Бизнес подтверждает этап или возвращает с комментарием.
- Подтверждённый этап: +10 баллов (один раз на критерий) и запись в профиле команды: задача, критерий, роли, отзыв бизнеса.
- Профиль — портфолио проверенных результатов: для резюме, следующей подработки и отчёта о практике.

### 8.3. Агенты

```ts

export const griller = new Agent({
  id: "griller",
  name: "Griller",
  model: process.env.LLM_MODEL ?? "anthropic/claude-sonnet-5",
  instructions: `Ты — тимлид студенческой команды разработчиков и аналитиков.
```

### 8.5. Workflow хода

```ts
import { createWorkflow, createStep } from "@mastra/core/workflows";

const classify = createStep({ id: "classify", /* classifier (nano) → fallback заглушка */ });
const extract  = createStep({ id: "extract",  /* card-extractor → keepGrounded() */ });
const decide   = createStep({ id: "decide",   /* код: уточнение / следующий узел / сводка */ });
const phrase   = createStep({ id: "phrase",   /* griller → проверки → fallback на шаблон */ });

export const grillTurn = createWorkflow({ id: "grill-turn", inputSchema: TurnInput, outputSchema: TurnOutput })
  .then(classify).then(extract).then(decide).then(phrase)
  .commit();
```

`analyze-draft`: `classify` по 17 узлам → `extract` по черновику → первый вопрос.

### 8.6. Проверки

| Проверка | Провал |
|---|---|
| `source_quote` — подстрока ответа (без учёта регистра, пробелов, пунктуации) | Поле отброшено, запись в `AiLog` |
| В `options` нет цифр | Варианты отброшены |
| `target` = запрошенный узел | Шаблонный вопрос |
| JSON проходит zod | 1 повтор, затем шаблон |
| Роль или навык не из справочника | Тег отброшен |
| Таймаут / ошибка LLM или nano | Шаблон и заглушка |
| `covered = true` без подтверждённой цитаты | Узел остаётся открытым |

`AiLog` хранит промпт, вход, сырой ответ, `parse_ok`, отброшенные поля, `fallback_used`.

### 8.7. Классификатор на GPT-5.4 nano

Быстрые решения «закрыт ли узел» и «какие роли нужны» — отдельный дешёвый агент на `openai/gpt-5.4-nano`. Он выбирает значения из enum и не пишет текст в карточку.

```ts
export const classifier = new Agent({
  id: "classifier",
  name: "Classifier",
  model: process.env.CLASSIFIER_MODEL ?? "openai/gpt-5.4-nano",
  instructions: `Определи по тексту пользователя, на какие узлы карточки уже есть ответ.
- covered = true только если ответ есть в тексте; evidence — точная подстрока текста.
- specificity: "specific" (число, формат, роль, срок, ссылка) или "vague".
- roles и skills — только значения из переданного справочника.`,
});

export const Classification = z.object({
  nodes: z.array(z.object({
    node: z.enum(NODE_IDS),
    covered: z.boolean(),
    evidence: z.string().optional(),
    specificity: z.enum(["specific", "vague"]),
  })),
  roles: z.array(z.enum(ROLES)),
  skills: z.array(z.enum(SKILLS)),
});
```

- `covered = true` без `evidence` или с цитатой, которой нет в тексте → узел остаётся открытым.
- Роли и навыки ограничены справочником через `z.enum`; бизнес подтверждает список.
- Ошибка или таймаут 5 с → заглушка на правилах (регэкспы: числа, URL, ключевые слова по узлам).
- `AI_ENABLED=false` → все агенты заменяются шаблонами и заглушкой.

## 11. Пример: бот статусов доставки

Черновик: «Мы логистическая компания. Операторы весь день отвечают клиентам, где их заказ. Хотим это автоматизировать. Контакт: it@logistics.example». Формат: подработка, «оплата за каждый принятый этап».
Подтверждены `context.current`, `context.change`, `users.role` («клиенты»), `link.contact` → **24, Черновик, 6-е место**. Стек и роли ИИ не угадывает — ставит вопросы в очередь.

**Дополнение 1 — блок «Данные и материалы»**
> **ИИ:** Какие данные получит команда? [выгрузка CSV] [документация API] [пример данных] [данных нет]
> **Бизнес:** Выгрузка статусов заказов в CSV и документация API в Swagger — ссылка. Переписка с клиентами — выгрузка из чата за 6 месяцев, около 50 тысяч сообщений.
> **ИИ:** Данные: статусы заказов (CSV), документация API (Swagger), выгрузка чата за 6 мес. Верно? → **Верно**

Один ответ закрыл три узла: формат, объём, пример (+20). **24 → 44, Рабочая, 4-е место.** Задача попадает в колоды.

**Дополнение 2 — блок «Критерии приёмки»**
> **ИИ:** По каким метрикам примете работу? [доля без оператора] [время ответа] [точность] [своё]
> **Бизнес:** Чтобы клиенты были довольны.
> **ИИ:** Как это измерить? Сколько обращений сейчас и какая доля должна закрываться без оператора?
> **Бизнес:** Сейчас все 300 обращений в день идут операторам. Бот должен закрывать хотя бы 60% и отвечать быстрее 3 секунд.
> **ИИ:** ① ≥60% обращений о статусе без оператора; ② ответ < 3 с. Масштаб проблемы: «300 обращений в день». Верно? → **Верно**

**44 → 59, Рабочая, 3-е место.**

| Блок | Старт | После доп. 1 | После доп. 2 |
|---|:-:|:-:|:-:|
| Контекст | 15 | 15 | 20 |
| Данные и материалы | 0 | 20 | 20 |
| Результат | 0 | 0 | 0 |
| Критерии | 0 | 0 | 10 |
| Ограничения | 0 | 0 | 0 |
| Пользователи | 5 | 5 | 5 |
| Связь | 4 | 4 | 4 |
| **Итого** | **24** | **44** | **59** |
| Пока неизвестно для исполнителя | данные, результат, критерии, стек, срок | результат, критерии, стек, срок | результат, стек, срок |

Следующие шаги: «Что сдаём?» (+15) → 74, Готовая; «Стек и роли?» (+3) → бизнес подтверждает [backend, бот-разработчик], [Python, REST API, Telegram Bot API, Docker] → 77.
BotForge видит задачу первой в колоде с совпадением 92%. У аналитиков DataBrew совпадение 28% — задача есть только в их каталоге.

## 13. Тесты

1. Черновик → прожарка → 24 → 59 → публикация → отклик BotForge → мэтч → стартовый пакет → этап → +10.
2. Один ответ закрывает несколько узлов (формат, объём, пример данных).
3. Задача с рейтингом 27: есть в каталоге, нет в колодах, отклик возможен.
4. Цитаты нет в ответе → поле отброшено, запись в `AiLog`.
5. Невалидный JSON / таймаут LLM → шаблонный вопрос.
6. Цифры в вариантах → варианты отброшены.
7. Два расплывчатых ответа на узел → одно уточнение.
8. «Данных нет» → 0 баллов, `data.volume` и `data.sample` пропущены.
9. Правка подтверждённого поля → баллы сняты до подтверждения.
10. Пустые `needed_roles` → задачи нет в колодах, есть подсказка бизнесу.
11. Отклонение без причины невозможно; закрытие без выбора работает.
12. Свайп ← не меняет рейтинг и место в каталоге.
13. `AI_ENABLED=false` → сценарий работает на шаблонах и заглушке.
14. Команда ищет практику → в колоде задачи с форматом «практика» и «оба»; в каталоге все.
15. Смена формата задачи не меняет рейтинг.
16. Переключение «Колода / Сетка» → тот же набор рекомендаций в том же порядке.
17. «Не сейчас» в сетке → задача исчезает из рекомендаций в обоих видах, каталог не меняется.
